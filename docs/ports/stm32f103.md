# STM32F103移植

工程在[`ports/stm32f103/`](../../ports/stm32f103/)提供一个可以
独立构建的裸机示例，不依赖STM32 HAL、CubeMX或操作系统。

同一份固件面向带PC13的STM32F103C系列容量型号，包括C4、C6、C8、
CB和CC。链接脚本按最小的C4配置限制为16 KB Flash和6 KB SRAM；因此
只要构建成功，固件也能放入拥有更多存储空间的C6、C8、CB和CC。

## 示例功能

- 在STM32F103C4/C6/C8/CB/CC中运行PIC10F200模拟器；
- 构建时根据`EXAMPLE`自动编译并嵌入所选PIC HEX固件；
- PIC GP0映射到STM32 PC13；
- STM32使用8MHz外部晶振和PLL，默认128MHz并可选择其他频率；
- PIC固件按4 MHz振荡器、1 MHz指令周期实时执行；
- PC13上的LED按照PIC固件状态闪烁。
- PA9通过USART1以115200、8N1输出启动过程和GP0变化日志。

常见Blue Pill板载LED连接在PC13与3.3V之间，低电平点亮。默认映射位于
`ports/stm32f103/include/board_config.h`：

```c
static const Stm32PicPinMap STM32_PIC_PIN_MAP[4] = {
    /* GP0 */ {GPIOC, 13u, 1u},
    /* GP1 */ {GPIOA,  0u, 0u},
    /* GP2 */ {GPIOA,  1u, 0u},
    /* GP3 */ {GPIOA,  2u, 0u}
};
```

每项依次是STM32 GPIO端口、引脚编号、是否反相。`gpio`为`0`表示不映射。
例如把GP1映射到PA0且不反相：

```c
/* GP1 */ {GPIOA, 0u, 0u}
```

## 引脚映射

| PIC10F200 | STM32F103C系列 | 说明 |
|---|---|---|
| GP0 | PC13 | 默认连接板载LED，低电平有效 |
| GP1 | PA0 | 普通输入/输出 |
| GP2 | PA1 | 普通输入/输出，也可供PIC固件用作T0CKI |
| GP3 | PA2 | PIC10F200的仅输入引脚 |

使用外接LED时，应串联约330Ω～1kΩ限流电阻。

调试串口使用PA9（USART1 TX）。将PA9连接到3.3V USB转串口模块的RX，
并将两者GND连接在一起。启动后可以看到时钟初始化、PIC初始化和GP0变化
日志；日志只在状态改变时输出，不会在每个模拟周期刷屏。

## 安装工具链

Ubuntu/WSL：

```sh
sudo apt update
sudo apt install gcc-arm-none-eabi binutils-arm-none-eabi openocd
```

## 构建

```sh
cd ports/stm32f103
make
```

默认构建`blink`。选择其他PIC10F200示例：

```sh
make EXAMPLE=button
make EXAMPLE=buzzer
make EXAMPLE=playmusic
```

也可以在项目根目录执行：

```sh
make stm32 EXAMPLE=button
```

STM32端口使用板载8MHz外部晶振和PLL，默认以128MHz运行：

```sh
make stm32 EXAMPLE=blink
```

调试日志默认关闭，构建出的程序不会初始化USART1，也不会执行时间戳计算、
十进制格式化或串口发送。需要查看启动过程和GP0变化时，显式加入`LOG=1`：

```sh
make stm32 EXAMPLE=blink LOG=1
make stm32 EXAMPLE=breathing_led CLOCK_MHZ=128 LOG=1
```

恢复无日志的正常运行版本：

```sh
make stm32 EXAMPLE=breathing_led LOG=0
```

`LOG`和`CLOCK_MHZ`一样属于构建配置。同一示例仍使用同一个build目录；
任一配置改变时，Makefile会自动重新编译全部对象文件。日志使用PA9
（USART1 TX，115200 8N1）。

可以通过`CLOCK_MHZ`选择频率：

```sh
make stm32 EXAMPLE=blink CLOCK_MHZ=48
make stm32 EXAMPLE=blink CLOCK_MHZ=72
make stm32 EXAMPLE=blink CLOCK_MHZ=128
```

支持`16、24、32、40、48、56、64、72、128`MHz。前八档不超过
STM32F103官方72MHz上限；128MHz是超频模式，不同芯片、温度和供电条件下
不保证稳定。

无论选择哪个频率，生成文件始终位于`build/blink/`。构建目录内的隐藏
频率戳会在`CLOCK_MHZ`改变时强制重新编译对象文件，避免混用旧频率产物。

Makefile会先调用对应示例的XC8构建，再使用`hex2c`生成通用符号
`pic_firmware_image`。平台源码中没有写死blink。

生成文件：

```text
build/<示例名>/picemu-stm32f103.elf
build/<示例名>/picemu-stm32f103.bin
build/<示例名>/picemu-stm32f103.hex
build/<示例名>/picemu-stm32f103.map
```

如果暂时没有ARM工具链，可以先检查C接口：

```sh
make host-check
make host-test
make host-test EXAMPLE=button
```

`host-test`会编译所选PIC固件，并确认自动生成的C映像与HEX完全一致。

## 使用ST-Link烧录

在Windows PowerShell中可以用一条命令完成以下全部步骤：调用WSL编译
PIC示例和STM32程序、通过ST-Link烧录、校验并复位运行：

```powershell
.\ports\stm32f103\scripts\program.ps1 -Example breathing_led
```

时钟、日志以及其他构建条件统一使用Makefile的`NAME=value`格式：

```powershell
.\ports\stm32f103\scripts\program.ps1 `
  -Example breathing_led CLOCK_MHZ=128 LOG=0
```

这些参数不在PowerShell脚本中重复定义，而是全部原样交给Makefile。以后
Makefile新增例如`FEATURE=1`的条件后，可以直接追加`FEATURE=1`，无需修改
烧录脚本。

脚本会自动查找`STM32_Programmer_CLI.exe`。如果安装在其他目录，可以指定：

```powershell
.\ports\stm32f103\scripts\program.ps1 `
  -Example blink `
  -Programmer "D:\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe"
```

连接SWDIO、SWCLK、GND和3.3V，然后执行：

```sh
make flash
```

等价的OpenOCD命令是：

```sh
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
  -c "program build/blink/picemu-stm32f103.elf verify reset exit"
```

## 实时调度原理

Cortex-M3的DWT周期计数器以所选`CLOCK_MHZ`频率递增。PIC10F200在
4MHz振荡器下的指令周期频率为：

```text
4 MHz / 4 = 1 MHz
```

所以一个PIC指令周期对应`CLOCK_MHZ`个STM32核心时钟。每执行一条PIC
指令，主循环按照该指令实际消耗的一个或两个PIC周期推进下一截止时间。如果解释器提前
完成，就等待DWT到达截止时间；如果STM32算力不足，则不再额外等待并以
能够达到的最高速度运行。这样不会因为跳转、调用或跳过指令的双周期行为
额外引入计时错误。

GPIO同步由通用`PicHardwareBridge`完成。平台回调只处理GP0，映射到
PC13；PIC核心本身仍然完全不知道STM32寄存器。

## 目录

```text
ports/stm32f103/
├── Makefile
├── stm32f103.ld
├── scripts/
│   └── program.ps1
├── tools/
│   └── hex2c.c
├── tests/
│   └── test_firmware.c
├── include/
│   ├── board_config.h
│   ├── debug_uart.h
│   ├── firmware.h
│   └── stm32f103_regs.h
└── src/
    ├── startup.c
    ├── debug_uart.c
    └── main.c
```

生成的固件C文件位于`build/<示例名>/generated/firmware.c`，不会提交到
仓库。STM32运行时不需要文件系统，也不需要解析HEX文本。

项目整体结构和桌面端、FPGA端之间的关系见
[项目架构](../architecture.md#固件在各平台的流向)。
